# 缩写提示（dsh-abbr-hint）

把鼠标停在 agent 回复里的缩写上，弹出一张卡片告诉你它是什么；解释可以当场改，改完整段对话同步生效。

## 安装

**从插件市场**：设置 → 插件市场，搜索「缩写」或 `dsh-abbr-hint`，一键安装。

**从压缩包**：解压后，在 DSH 里让 agent 调 `plugin_manager` 的 `install_bundle`，目标填解压出来的目录绝对路径；然后**重启一次应用**（宿主半边的代码只在进程启动时加载）。

装好后打开 设置 → 缩写提示，能看到开关和词典。


## 用法

| 动作 | 结果 |
|---|---|
| 鼠标停在缩写上 | 约 70ms 后弹出解释卡片（已收录的缩写带虚线下划线） |
| 点一下缩写 | 卡片固定住并直接进入编辑：改写解释 → Enter 或「保存」 |
| **在卡片里点击或输入** | 卡片自动「钉住」：光标在卡片里时，鼠标怎么动都不会让它消失；输入内容也不会触发宿主快捷键 |
| **卡片里追问一句** | 输入框写「它和 X 有什么区别」并回车，稍等几秒，卡片里多出一段**详细解释**（问的时候会带上这条回复的上下文） |
| 不写问题直接点「问」 | 让模型把这条缩写展开讲一遍 |
| **没收录的缩写** | 插件自己把缩写连同所在回复发给模型，自动生成一条释义并**直接收录**（默认开启，设置页可关；每条带「自动」标记） |
| 没收录的缩写（手动） | 同样能悬停/点击，卡片显示「未收录」，可以当场补一条 |
| **选中任意一段文字 → 右键** | 弹出小菜单：「生成悬停解释」立刻让模型写一句释义并收录，从此这段文字（中文、短语、大小写混写都行）都能悬停；菜单里也有「复制选中文本」 |
| Esc / 点别处 / 滚动 | 关掉卡片 |
| 设置 → 缩写提示 | 开关功能、开关自动补全、搜索/编辑/删除/新增词条、看追问接口与自动补全状态、恢复内置词典 |

选中生成有两个细节：命中范围只认 agent 回复里的选区（选区超过 40 字、或全是标点就不接管右键）；如果这段文字**已经有解释**，按钮会变成「重新生成解释」并且要点两次确认，避免手滑覆盖你写的内容。

菜单什么时候消失：**没有定时器**。鼠标离开菜单（或离开右键的位置）就消失；按在别处、Esc、滚动、点右上角 × 也消失。生成结果会一直留在菜单里，你想看多久看多久；生成过程中就算鼠标移开，释义照样会写进词典，只是不再更新那张已经消失的菜单。

改过的解释存在浏览器 `localStorage` 的 `dsh-abbr-hint.v1` 键里，对这台机器的这个应用长期有效；删除的内置词条不会被「默认词典」重新塞回来。详细解释单独存在同一个文档的 `details` 字段里，可以逐条「清除」。

### 自动补全的边界

- **只补「没有解释」的缩写**：内置词典里有的一律不覆盖，也不覆盖你手写或改过的；你一编辑某条自动释义，它就变成你的版本（「自动」标记消失）。
- **删掉的不会再回来**：删过的缩写进删除名单，自动补全会跳过它。
- **有预算**：每页最多补 60 个、每批 6 个、同时最多 2 个请求；连续失败 3 次就停手（设置页会写明原因），不会一直打接口。
- **会外发内容**：自动补全把「缩写 + 它所在那条回复的片段」发给这个 profile 自己的模型路由。不想发就把它关掉，悬停和手动编辑不受影响。

追问走的是这个应用自己的 `/api` 通道（`/api/abbr-hint.explain`、`/api/abbr-hint.fill`），由插件宿主半边调用本 profile 当前默认的模型路由：所以它和你在界面上用的模型是同一条线，但**不带这一整个会话的历史**——它只拿得到缩写在的那条回复原文。要问需要全对话记忆的问题，还是在对话里直接问我。

## 它怎么做到不碰宿主的 DOM

标注走 **CSS Custom Highlight API**：插件只创建 `Range` 交给 `CSS.highlights`，由样式表里的 `::highlight()` 着色，宿主的 React 树一个节点都没被动过，流式回复、会话切换、复制文本都不受影响。命中测试用 `caretRangeFromPoint` 给出的精确 `(文本节点, 偏移)`，到插件自己记的区间表里查一次——不做几何估算，也不拼整条消息的文本。

只标注渲染完成的 agent 回复（`[data-chat-flow-kind="assistant-step"]`），跳过代码块、链接、按钮、输入框和插件自己的 UI；行内代码里的缩写仍然可悬停（那通常正是最想查的词）。

词典里的词条分两档匹配：拉丁字母开头的「词形」词条按 ASCII 词边界匹配且不区分大小写（所以选中 `MoE` 之后 `moe` 也认），其它词条（中文、带空格的短语）按字面整串匹配——这样选中什么就能悬停什么。

追问走 `/api` 而不是另开端口：`ctx.connection.fetch.register` 在应用自己的已鉴权 Fetch 桥上占三个精确端点，浏览器与 Desktop 的 shell 载体都走同一条路，也自动继承回环/信任/鉴权的边界。

## 文件

| 文件 | 作用 |
|---|---|
| `package.json` | 清单：`dsh.bundle.patch` + `dsh.client`（`platform: web`、`immediately`） |
| `cordis.patch.yml` | 插入 `abbr-hint` 这一行 |
| `index.js` | Host 半边：`/api/abbr-hint.explain`（追问 / 选中释义）、`/api/abbr-hint.fill`（批量自动补全）、`/api/abbr-hint.ping`（状态）三个精确 Fetch 端点，都调用本 profile 的默认模型路由 |
| `client.js` | 全部界面实现：词典、扫描、标注、悬停卡片、追问、选中右键菜单、自动补全队列、设置页 |
| `test/check.cjs` | 浏览器半边的无头自检：匹配规则（含中文/短语/大小写）、选区归一、词条增删、详细解释、自动标记、持久化、恢复默认 |
| `test/host-check.mjs` | 宿主半边的无头自检：端点注册、请求解析、提示词内容、批量释义解析、输入上限、失败信封 |

自检（在插件目录下）：

```powershell
node test/check.cjs
node test/host-check.mjs
```

**改了 `index.js` 必须重启应用**：宿主进程把上一代模块留在内存里，重新 enable 不会重新 import（DSH 的既有约束）。改 `client.js` 只需要刷新页面。

浏览器控制台里还有一个只读句柄 `window.__dshAbbrHint`（`store`、`match(text)`、`rescan()`、`count()`、`cardOpen()`），排查时用得上。

## 卸载

设置 → 插件里移除，或让 agent 调 `plugin_manager` 的 `remove_bundle`，目标 `dsh-abbr-hint`。插件删除后页面里的下划线、卡片、设置页一起消失，不会留残留节点。
